# Задание 1. Исследование моделей и инфраструктуры

> Полный отчёт: [`docs/task-1-research.md`](docs/task-1-research.md)

## 1. LLM: локальные Hugging Face vs облачные OpenAI / YandexGPT

| Критерий | Локальные (Qwen2.5-32B, Llama 3.3 70B) | OpenAI (GPT-4o / 4o-mini) | YandexGPT Pro |
|---|---|---|---|
| Качество | Высокое на RU/EN и коде; 70B лучше в EN, но тяжелее | Эталонное у GPT-4o; 4o-mini немного уступает | Сильный русский, слабее EN и код |
| Скорость | 35–60 ток./с (32B), 20–35 ток./с (70B) | 60–120 ток./с, TTFT 0,2–0,8 с | 30–60 ток./с |
| Стоимость | GPU-сервер: €700–1 200/мес. (32B), €1 800–3 000/мес. (70B) | $0,15/$0,60 за 1 млн токенов (4o-mini), $2,50/$10 (4o) | Тарифы Yandex Cloud |
| Развёртывание | GPU, vLLM, квантование, мониторинг | API-ключ и SDK | API-ключ, аккаунт в РФ |
| Конфиденциальность | Полная | Данные уходят вендору | Данные в РФ — неприемлемо для ЕС |

**Вывод:** Qwen2.5-32B AWQ — для confidential/restricted; GPT-4o-mini — fallback для public/internal. YandexGPT не подходит из-за юрисдикции РФ.

## 2. Эмбеддинги: Sentence-Transformers vs OpenAI Embeddings

| Критерий | bge-m3 | e5-large | OpenAI 3-small | OpenAI 3-large |
|---|---|---|---|---|
| Скорость индексации | GPU — минуты; CPU — часы | GPU — минуты; CPU — часы | Зависит от лимитов API | Медленнее small |
| Качество | Сильное на RU/EN и коде; dense + sparse | Сильное на RU, слабее EN и код | Хорошее EN, среднее RU | Очень сильное EN, хорошее RU |
| Стоимость | ~€0 (свой GPU) | ~€0 (свой GPU) | $0,02 за 1 млн токенов | $0,13 за 1 млн токенов |
| Конфиденциальность | Полная | Полная | Данные уходят | Данные уходят |

**Вывод:** BAAI/bge-m3 — мультиязычность, 8k контекст, dense + sparse для гибридного поиска, работа on-prem.

## 3. Векторные хранилища: FAISS vs ChromaDB

| Критерий | FAISS | ChromaDB |
|---|---|---|
| Скорость поиска top-10 | Flat: 3–10 мс; HNSW: < 1 мс | Embedded: 2–5 мс; server: 5–15 мс |
| Скорость индексации | Секунды-минуты | Десятки секунд-минуты |
| Сложность внедрения | Библиотека в приложении; нужен свой слой метаданных/ACL | Проще «из коробки»; server-режим добавляет сервис |
| Удобство | Полный контроль, воспроизводимость | Встроенные метаданные, `where`-фильтры, CRUD |
| Стоимость владения | Бесплатно; сложность в разработке обвязки | Бесплатно; сложность в эксплуатации сервиса |
| Масштабирование | Нет распределённого режима; путь — Qdrant | OSS — один узел; Chroma Cloud — платно |

**Вывод: FAISS.** Для корпуса из 21 тыс. документов даёт точный поиск за миллисекунды, не требует отдельного сервиса и полностью локален. ACL — отдельными индексами по доменам. ChromaDB — для прототипов; при росте до миллионов векторов — Qdrant.

## 4. Конфигурация сервера

| Профиль | CPU | RAM | GPU | Диск |
|---|---|---|---:|---|
| Dev / пилот | 8 vCPU | 32 ГБ | 1×RTX 4090 24 ГБ | 500 ГБ NVMe |
| **Prod** | **16 vCPU** | **64 ГБ** | **1×L40S 48 ГБ или A100 40 ГБ** | **1 ТБ NVMe** |
| Prod + HA | 2×16 vCPU | 2×64 ГБ | 2×L40S | 2 ТБ NVMe |
| Под 70B | 16–32 vCPU | 128 ГБ | 1×H100 80 ГБ | 2 ТБ NVMe |

32B в 4-bit занимает ~18–20 ГБ VRAM + 4–8 ГБ KV-кэш, поэтому 24 ГБ мало, 40–48 ГБ — безопасный минимум. Индекс FAISS для такого корпуса помещается в RAM; CPU-инференс 32B слишком медленный для интерактивного бота.

## 5. Варианты и выбор

| Вариант | Состав | Сильные стороны | Ограничения | Стоимость |
|---|---|---|---|---|
| A. Cloud-first | GPT-4o + OpenAI embeddings + FAISS | Лучшее качество, минимум ops | Все данные уходят в облако, GDPR | Оплата за токены + хостинг |
| B. Local-first | Qwen2.5-32B + bge-m3 + FAISS | Полная конфиденциальность | Дорого, нужен MLOps, нет fallback | GPU-сервер + MLOps |
| **C. Hybrid** | Локальные Qwen2.5-32B + bge-m3 + FAISS; GPT-4o-mini для public/internal | Приватность по умолчанию + гибкость | Сложнее маршрутизация | GPU + небольшие расходы на API |
| D. Managed RAG | Azure OpenAI (EU) + Qdrant/Chroma Cloud | Минимум ops, масштабируемость | Знания у вендоров, lock-in | Подписка + токены |

**Почему C:** confidential/restricted обрабатываются локально; public/internal могут использовать GPT-4o-mini. A не проходит по конфиденциальности, B избыточен по стоимости и ops, D хранит знания у вендоров и создаёт lock-in. **Рекомендация — C.**

## 6. Результат: выбор векторной БД

Для бота выбирается **FAISS** (`IndexIDMap2` + `IndexFlatIP`). Причина: корпус из 21 тыс. документов не требует распределённой БД, точный поиск занимает миллисекунды, не нужен отдельный сервис, решение полностью локально и соответствует требованиям конфиденциальности. ACL реализуется отдельными индексами по доменам доступа, метаданные хранятся в PostgreSQL. ChromaDB остаётся для прототипов, миграция при росте — на Qdrant.

# Задание 4. RAG-бот с техниками промптинга

> Примеры диалогов: [`index/rag_examples.md`](index/rag_examples.md)

## 1. Пайплайн

| Шаг | Что происходит | Где |
|---|---|---|
| 1 | Текстовый запрос пользователя | `POST /chat` |
| 2 | Эмбеддинг тем же энкодером, что строил индекс | `tools/embedding.py` (`BgeM3`) |
| 3 | Поиск `top-k` ближайших чанков в FAISS | `tools/search_index.py` |
| 4 | Готовая цепочка LangChain `RetrievalQA` (`chain_type="stuff"`): промпт из system (CoT), few-shot и найденных фрагментов | `tools/rag_bot.py` (`PROMPT`, `_chain`) |
| 5 | Вызов LLM через OpenAI-совместимый API; без ключа — заглушка `DemoChat` | `tools/rag_bot.py` (`OpenAICompatibleChat`) |
| 6 | Ответ + источники для цитирования | `POST /chat` |

- `tools/rag_bot.py` — ядро: `answer()`, `retrieve()`, `build_prompt()`, `demo_answer()` и сборка `RetrievalQA` в `_chain()`.
- `tools/api.py` — REST-сервис FastAPI.
- `docker-compose.yml` — запуск сервиса в контейнере.

Цепочка не написана вручную: используется готовая `RetrievalQA` из `langchain-classic`. Поиск в FAISS выполняется до неё, чтобы отказ по порогу срабатывал раньше вызова LLM; цепочке передаются уже найденные документы через собственный `BaseRetriever`, а она собирает промпт и вызывает модель.

## 2. Техники промптинга

**Few-shot.** В промпт добавлены два примера Q/A из этой же базы знаний — ответы сверены с реальными чанками `aran-velmor-001` и `the-synth-flux-001`, а не придуманы.

**Chain-of-Thought.** System-промпт требует сначала размышлять по шагам (какой фрагмент отвечает → какие в нём факты → вывод), и только потом давать итоговый ответ. Опираться разрешено только на предоставленные фрагменты.

**«Я не знаю».** Два уровня защиты:

1. До вызова LLM: если лучший чанк ниже порога `SCORE_THRESHOLD` (по умолчанию `0.45`), бот отвечает отказом.
2. В промпте: если во фрагментах нет ответа, модель должна ответить ровно «Я не знаю».

Порог подобран эмпирически: релевантные вопросы дают ≥ 0.465, явно посторонние («погода», «борщ») — ≤ 0.432. На кросс-языковых запросах распределения частично пересекаются, поэтому в реальном режиме дополнительно работает инструкция LLM.

## 3. Интерфейс: REST API

```bash
docker compose up --build
```

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/chat` | Вопрос → ответ с источниками |
| `GET` | `/health` | Живость и текущий режим (LLM/демо) |
| `GET` | `/docs` | Swagger UI |
| `GET` | `/redoc` | ReDoc |
| `GET` | `/openapi.json` | Схема OpenAPI 3.1 |

```bash
curl -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"query": "Кто такой Арэн Велмор?"}'
```

Swagger UI (`http://localhost:8000/docs`) даёт готовые примеры запроса и ответа, описания всех полей и коды ошибок. Проверка без curl: `POST /chat` → **Try it out** → выбрать пример или ввести вопрос → **Execute**.

Переменные окружения: `OPENAI_API_KEY` (без него — демо-режим), `OPENAI_BASE_URL`, `LLM_MODEL`, `TOP_K`, `SCORE_THRESHOLD`. Ключ в код не попадает — передаётся через окружение.

## 4. Проверка

- 5 успешных диалогов и 2 случая «Я не знаю» — в `index/rag_examples.md`.
- Демо-режим работает без ключа: ответ собирается из найденного фрагмента с шагами CoT.
- С `OPENAI_API_KEY` тот же промпт уходит в LLM, и ответ генерируется на русском.
- Источники в ответе содержат `source`, `heading`, `start_char`/`end_char` — по ним бот может дать точную цитату.
